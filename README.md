# CIRCA Enterprise (v3): secure packaging verification and Scope-3 tracking

FastAPI + SQLAlchemy + PostgreSQL/SQLite, JWT auth (bcrypt), USER/ADMIN roles, rate limiting, OpenCV/pyzbar QR verification.

## Run locally in VS Code (from the repo root)
```bash
python -m venv .venv && source .venv/bin/activate        # Windows: .venv\Scripts\Activate.ps1
pip install -r requirements.txt
cp .env.example .env                                      # Windows: copy .env.example .env
```
Edit `.env`: set `JWT_SECRET` and `SERIAL_SECRET` (generate with `python -c "import secrets;print(secrets.token_urlsafe(48))"`),
and `ADMIN_EMAIL` / `ADMIN_PASSWORD` (12+ chars). Then:
```bash
python -m backend.seed          # creates tables, 300 serials, admin, dev demo user, ./sample_qr/*.png
uvicorn backend.app:app --reload
```
Open http://127.0.0.1:8000 . Dev docs at /docs. Analytics: `python -m analytics.analytics`.

## Test checklist
1. Log in as your ADMIN_EMAIL: the "Brand Admin" tab appears. A normal account never sees it, and GET /metrics returns 403 for it.
2. Log in as demo@circa.example / DemoPass2026! (dev only). Upload a file from ./sample_qr. Expect "Verified". Click Claim reward.
3. Upload the same QR again: "already_redeemed" (409). Claim twice: "already_claimed" (409).
4. Send 6 wrong logins within a minute: HTTP 429.
5. Admin: add a product, issue a batch, export the CSV, open a [QR] to scan with your phone camera.
Camera notes: live scan needs localhost or HTTPS and a Chromium browser; otherwise use "Capture / upload photo".

## Deploy: Render + (Render PostgreSQL or Supabase)
1. Push the repo to GitHub.
2. Render > New > Blueprint > pick the repo (reads render.yaml: web service + free PostgreSQL).
3. When prompted, enter ADMIN_EMAIL and ADMIN_PASSWORD (12+ chars). JWT_SECRET and SERIAL_SECRET are generated by Render.
4. After the build, open https://<your-service>.onrender.com and log in as the admin. Check /health.
5. Supabase instead: create a project, copy the pooler connection string, append `?sslmode=require`, and set it as DATABASE_URL on the Render service (remove the `databases:` block from render.yaml).
6. Rotating SERIAL_SECRET invalidates every printed code. Keep it in a secret manager and back it up.
Free-tier sleep and database expiry rules change; check the provider's current terms.

## Security controls implemented
- bcrypt hashing (cost 12), JWT with expiry, role re-read from the database on every request, self-registration is always USER.
- RBAC: /metrics and /admin/* require ADMIN; users only read their own footprint; claims are scoped to the token's user.
- Rate limits: login 5/min, register 5/10 min, verify 30/min, default 120/min per IP; 10 invalid codes per 10 min locks a user's scanning.
- Double-claim defence: row lock + status change + UNIQUE(serial_id) on transactions. HMAC-signed serials reject forged codes before any DB lookup.
- Upload type/size limits, SQL via SQLAlchemy ORM only, HTML escaping in the UI, security headers + CSP, strict CORS, docs disabled in production, fail-closed secret checks.

## Known gaps (do before real customers)
- Rate limiter is in-process memory: use Redis if you run more than one instance.
- No email verification, password reset, MFA, refresh tokens or token revocation. The JWT is kept in sessionStorage (XSS-exposed); move to httpOnly cookies + CSRF protection for a hardened build.
- No Alembic migrations, automated tests, audit log, or monitoring. CSP allows inline scripts and the Tailwind CDN: compile Tailwind and use nonces.
- Serial issuance keys need a managed key process; HMAC tag is 40 bits, backed by the rate limits above.
- Emission factors are indicative values: replace with supplier LCA data. CO2e covers packaging material only.
- Run a dependency scan (pip-audit) and an independent security review.
